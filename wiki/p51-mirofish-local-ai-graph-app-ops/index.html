P24 / AI 운영 / 그래프 앱

MiroFish 로컬 AI 그래프 앱 운영

클라우드 API, Zep, 외부 Graphiti와 Neo4j에 기대던 MiroFish를 로컬 Ollama, 로컬 임베딩, Neo4j 기반의 사내망 분석과 보고 환경으로 옮기고, 읽기 전용 데모와 리포트 export까지 정리했습니다.

2026
AI운영그래프앱

Local AI graph app

클라우드 의존형 MiroFish를 사내망에서 돌리는 로컬 AI 분석 환경으로 옮겼습니다.

원본 MiroFish는 외부 API와 Zep 기반 그래프 구축에 기대는 구조였습니다. 저는 그 의존을 줄이고, Ollama, 로컬 임베딩, Neo4j, Graphiti를 묶어 입력 문서부터 시뮬레이션, 보고서 export까지 이어지게 만들었습니다.

의존 제거 API / Zep / cloud graph

외부 API와 Zep Cloud 의존을 로컬 Ollama, Neo4j, Graphiti 구성으로 옮겼습니다

로컬 모델 gemma + qwen embedding

시뮬레이션과 임베딩을 사내망에서 먼저 돌릴 수 있게 구성했습니다

Fallback server-led tools

모델의 tool-calling 실패를 서버가 도구 실행 후 LLM 작성만 맡기는 방식으로 우회했습니다

산출물 PDF / DOCX / HTML

시뮬레이션 결과를 읽기 전용 데모와 문서 export로 전달할 수 있게 정리했습니다

Pipeline

입력 문서에서 그래프, 시뮬레이션, 보고서 export까지 한 흐름으로 묶었습니다.

AI 앱은 모델 호출만으로 업무에 들어가지 않습니다. 로컬 모델, 그래프 DB, 상태 복구, fallback, 리포트 export가 함께 맞아야 실제 업무에 연결됩니다.

01 Input

입력 문서와 시뮬레이션 요구사항을 읽기 전용 데모에서 확인합니다

02 Prepare

엔티티, 관계 타입, 에이전트 환경과 라운드 조건을 준비합니다

03 Simulate

그래프와 에이전트 액션 로그를 보며 멀티에이전트 시뮬레이션을 재생합니다

04 Report

근거 수집과 최종 작성 모델을 분리해 보고서를 생성합니다

05 Export

PDF, DOCX, Markdown, 인쇄용 HTML로 결과물을 전달합니다

개요 역할 문제 결정 과정 검증 결과 근거 자료

개요

  • MiroFish는 멀티에이전트 그래프 시뮬레이션을 통해 입력 문서에서 엔티티와 관계를 만들고, 시뮬레이션 결과를 보고서로 산출하는 AI 분석 앱입니다.
  • 원본 구조는 OpenAI API, Zep Cloud, 클라우드 Graphiti/Neo4j 의존이 강했기 때문에 사내망에서 안전하게 검증하려면 로컬 LLM과 로컬 그래프 스택으로 바꿔야 했습니다.

역할

원본 MiroFish의 클라우드 의존 구조를 분석하고, OpenAI API, Zep Cloud, 외부 그래프 스택을 로컬 Ollama, qwen 계열 임베딩, Neo4j, Graphiti 구성으로 바꿨습니다. 한글 입력과 출력이 깨지지 않도록 UI, API, 로그 경로를 점검하고, 모델의 native tool-calling 실패를 서버 주도 도구 실행 후 LLM 작성으로 우회해 시뮬레이션과 보고서 생성 흐름을 안정화했습니다.

문제

  • 외부 API 중심 도구는 내부 전략 문서나 민감한 업무 시나리오를 그대로 넣기 어렵습니다. LLM, embedding, graph database, 보고서 export가 모두 로컬 또는 통제 가능한 경로에서 돌아가야 했습니다.
  • 로컬 모델은 native tool-calling을 안정적으로 반환하지 않는 경우가 있었고, 한글 UI와 로그에서는 인코딩 깨짐이나 중국어 잔여 문구도 함께 정리해야 했습니다.
  • 시뮬레이션은 여러 단계의 상태를 이어 가기 때문에 run state, graph snapshot, action rendering이 꼬이면 같은 입력에서도 결과를 재현하기 어렵습니다.

내가 한 결정

  • OpenAI API 호출은 로컬 또는 원격 Ollama로 바꾸고, Zep Cloud 의존은 제거하거나 우회했으며, Graphiti와 Neo4j는 로컬 실행을 기준으로 다시 묶었습니다.
  • 시뮬레이션과 근거 수집은 로컬 모델을 우선 사용하고, 최종 보고서 작성 품질 비교가 필요할 때만 외부 고성능 모델을 단계별로 주입할 수 있게 라우팅을 나눴습니다.
  • tool-calling은 모델이 직접 도구를 호출한다는 전제를 버리고, 서버가 검색, 그래프, 인터뷰 결과를 먼저 만든 뒤 LLM에는 최종 작성만 맡기는 fallback 구조로 바꿨습니다.

과정

  • 입력 문서, 시뮬레이션 요구사항, 환경 준비, 시뮬레이션 재생, 최종 보고서로 이어지는 읽기 전용 데모 플로우를 구성했습니다.
  • 원본 중국어 UI와 Zep 기반 그래프 구축 화면을 기준으로 before 상태를 남기고, 한국어 엔티티와 관계 그래프가 로컬 환경에서 생성되는 after 상태를 비교했습니다.
  • mojibake와 한글 표시 문제는 프런트 표시, API 응답, 시뮬레이션 로그 경로에서 각각 방어했습니다.
  • 재실행 시 이전 run 상태가 섞이지 않도록 run_state 정합성을 확인하고, 원격 그래프가 없을 때는 graph_snapshot.json으로 렌더링하는 fallback을 두었습니다.
  • 결과물은 PDF, DOCX, Markdown, 인쇄용 HTML로 export할 수 있게 정리했습니다.

검증

  • 외부 API 없이도 입력 문서 확인, 환경 준비, 시뮬레이션 재생, 보고서 생성까지 Step1-5 전체 흐름이 화면상 이어지는지 확인했습니다.
  • 로컬 gemma 계열 모델 단독 구성과 외부 고성능 작성 모델 혼합 구성을 같은 입력에서 비교할 수 있는 라우팅 구조를 확인했습니다.

결과

  • 클라우드 의존형 AI 분석 앱을 외부 API 없이 사내망에서 입력 문서부터 보고서 export까지 돌아가게 만들었습니다.
  • 입력, 그래프, 시뮬레이션 상태, fallback, 리포트 산출까지 하나의 시스템으로 묶어 돌렸습니다.

근거 자료

  • 원본 중국어 UI와 Zep 의존 그래프, 로컬화 후 한국어 엔티티 그래프 비교
  • 읽기 전용 데모: 입력 문서, 환경 준비, 시뮬레이션 재생, 최종 보고서 화면
  • 로컬 Ollama gemma4:31b, qwen3-embedding:8b, Neo4j와 Graphiti 기반 모델과 그래프 구성
  • PDF, DOCX, Markdown, 인쇄용 HTML report export 구조
