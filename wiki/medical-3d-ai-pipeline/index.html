의료 3D AI 파이프라인

CT 분할 모델 후보 4종을 같은 테스트셋으로 비교해 nnU-Net v2 파인튜닝을 골랐고, DICOM 입력부터 부위별 STL까지 자동으로 도는 파이프라인을 만들어 사내에서 운영하고 있습니다. 2026년 9월까지 1,228건을 실행했고, 여기서 나온 STL이 제가 만든 보형물 설계 자동화 도구의 입력이 됩니다.

Model decision

최신 모델보다, 매일 돌릴 수 있는 모델이 필요했습니다.

2D TransUNet은 빠르고 가벼웠지만 512x512 입력 기반이라 3D 메쉬로 올리면 해상도가 떨어지고 슬라이스 사이가 끊겼습니다. 3D TransUNet과 U-Mamba는 서버를 들인 뒤 같은 데이터셋으로 학습하고 같은 테스트셋으로 평가했습니다. 분할 품질은 nnU-Net v2와 오차 범위 안이었지만 추론 시간이 약 두 배 걸려, 매일 돌리는 운영에는 nnU-Net v2 파인튜닝을 택했습니다.

AI infrastructure

고른 모델을 운영에 올리고 3D 후보까지 비교하려고, 학습 서버를 직접 들였습니다.

처음에는 회사에 학습용 GPU가 없어, 협업 연구실의 RTX 5080에서 nnU-Net v2와 2D TransUNet을 먼저 비교했습니다. 3D 후보인 3D TransUNet과 U-Mamba는 그 장비의 VRAM으로는 올릴 수 없었습니다. 서버는 이미 고른 모델을 운영에 올리고, 3D 모델 비교와 대형 LLM 실험까지 한 장비에서 하는 것을 기준으로 골라 RTX PRO 6000 96GB 도입을 제안했고, Linux 기반 학습과 추론 환경을 직접 구성했습니다. 서버를 들인 뒤에는 3D 후보도 같은 데이터셋과 테스트셋으로 비교했습니다.

지금 쓰임 CT + LLM

Operations

수동 40~90분 걸리던 CT 분할과 STL 정리를, 평균 7.4분 자동 처리로 1,228건 돌렸습니다.

DICOM 변환부터 5-fold 추론, 후처리, STL 변환까지 한 번에 자동으로 도는 시간이고, 사람이 검토하는 시간은 뺐습니다.

Final review

최종 결과는 CT 단면과 3D 화면에서 다시 맞춰봤습니다.

왼쪽은 원본 DICOM 단면 위 분할 contour, 오른쪽은 같은 결과를 올린 3D mesh입니다. 단면에서 잡은 경계가 3D에서도 해부학적 위치에 맞는지 한 화면에서 검토합니다.

Outputs

mask에서 끝내지 않고, 설계자가 볼 수 있는 3D 산출물까지 묶었습니다.

제가 이 작업에서 중요하게 본 부분은 AI 결과를 실제 설계 검토 흐름까지 넘기는 것이었습니다. 그래서 mask, mesh, STL, preview를 따로 떨어뜨리지 않고 한 흐름으로 묶었습니다.

Dataset preparation

모델보다 먼저, 학습 가능한 데이터셋을 만들어야 했습니다.

이 작업에서 가장 오래 걸린 부분은 모델 학습보다 데이터셋이었습니다. 내부 CT 작업 데이터를 선별하고 다시 가공해 77케이스, CT 37,826슬라이스 학습 데이터셋을 만들었습니다. 내부 세그멘테이션 프로그램이 지원하는 포맷이 적어서, 부위별 흑백 라벨 이미지를 3D label volume으로 다시 합치는 과정을 직접 만들었습니다.

training source 77 cases / 37,826 slices

내부 작업 데이터 중 학습에 사용할 수 있는 케이스를 선별하고 다시 가공했습니다.

legacy tool 내부 세그멘테이션

지원 포맷이 제한적이라 바로 학습 데이터로 넘기기 어려웠습니다.

grayscale labels 부위별 흑백 export

skin, bone, airway, 기삽입 라벨을 각각 이미지로 분리했습니다.

volume rebuild 2D label에서 nii.gz로

slice 순서와 CT 기준을 맞춰 3D 학습 label volume으로 다시 합쳤습니다.

train ready nnU-Net dataset

모델이 읽을 수 있는 입력 CT와 multi-label mask 구조로 정리했습니다.

Label normalization

작업자마다 달랐던 라벨을 하나의 규칙으로 다시 맞췄습니다.

제가 오기 전부터 진행된 데이터가 섞여 있었기 때문에, 라벨 이름이 케이스마다 다르거나 아예 빠진 경우도 있었습니다. 먼저 라벨이 있는 케이스와 없는 케이스를 나누고, 이름 규칙이 다른 라벨은 Python으로 최대한 분리한 뒤, 자동으로 처리되지 않는 케이스는 다시 확인했습니다.

raw condition 라벨 있음 / 없음 / 이름 다름

기존 작업자마다 저장 방식이 달라서 파일만 보고 바로 학습 데이터로 묶을 수 없었습니다.

sorting pass Python 기반 1차 분류

폴더명, 파일명, 이미지 채널, 라벨 후보를 기준으로 자동 정리 가능한 케이스를 먼저 걸렀습니다.

manual repair 누락 케이스 수동 보정

라벨이 없거나 애매한 케이스는 직접 확인해서 다시 라벨링하고 학습 대상에서 쓸 수 있게 맞췄습니다.

Model comparison

같은 테스트셋으로 비교하고, 운영 기준으로 골랐습니다.

후보 4종(2D TransUNet, 3D TransUNet, U-Mamba, nnU-Net v2)을 같은 테스트셋으로 비교해, 결과 해상도, 추론 시간, 재학습과 유지보수 난이도를 함께 봤습니다. 논문 수치보다 제 데이터와 같은 테스트셋으로 재현한 비교를 기준으로 삼았고, 제 환경에서는 nnU-Net v2를 파인튜닝하는 쪽이 가장 현실적이었습니다.

2D TransUNet 빠르지만 3D 품질이 부족했습니다.

학습과 추론은 가벼웠지만 512x512 resize 기반 결과가 목표 해상도에 닿지 못했습니다.

3D TransUNet 품질은 비슷했고, 추론 시간이 약 두 배였습니다.

처음 쓰던 장비의 VRAM으로는 올릴 수 없어, 서버를 들인 뒤 같은 데이터셋으로 학습하고 같은 테스트셋으로 평가했습니다. 품질은 nnU-Net v2와 오차 범위 안이었고, 추론 시간이 약 두 배였습니다.

U-Mamba 품질은 비슷했고, 추론 시간이 약 두 배였습니다.

3D TransUNet과 같은 조건으로 서버 도입 뒤 비교했습니다. 품질은 nnU-Net v2와 오차 범위 안이었고, 추론 시간이 약 두 배였습니다.

nnU-Net v2 충분한 품질과 운영 가능성의 균형이 맞았습니다.

3D 후보와 품질은 같은 수준이면서 추론 시간은 절반 정도였고, 파인튜닝, 재현성, 후처리 연결까지 고려하면 가장 현실적인 선택이었습니다.

CT-to-mesh pipeline

좌표를 잃지 않고 mask에서 mesh/STL까지 이어지게 만들었습니다.

의료용 3D 데이터는 일반적인 화면 좌표처럼 다루면 쉽게 틀어집니다. DICOM에서 NIfTI로 넘어갈 때 spacing, orientation, slice order를 보존해야 했고, LPS 좌표계를 설계자가 쓰기 쉬운 world 기준으로 변환하는 후처리도 필요했습니다.

01 DICOM에서 기준 nii.gz로

원본 CT의 spacing과 orientation을 먼저 확보했습니다.

02 label volume 정렬

흑백 라벨 이미지를 CT 기준 slice와 맞춰 multi-label volume으로 합쳤습니다.

03 nnU-Net v2 inference

파인튜닝된 모델로 skin, bone, airway, prosthesis mask를 추론했습니다.

04 LPS에서 design world로

의료 좌표계를 실제 설계 검토가 쉬운 방향과 위치로 보정했습니다.

05 mesh / STL / preview

후처리된 산출물을 부위별 mesh와 검토 가능한 STL로 정리했습니다.

Where it goes next

분할 결과는 설계 자동화와 사내 웹서비스로 바로 이어집니다.

설계팀은 제가 만든 CT 분할 웹 서비스에서 CT를 올리고, 진행률과 로그를 보며 STL을 내려받습니다. 여기서 나온 뼈와 피부 STL은 보형물 설계 자동화 도구의 입력으로 들어가고, 그 도구가 만든 몰드는 MoldTrace에서 제조 컨펌 대화와 함께 다시 확인합니다.
