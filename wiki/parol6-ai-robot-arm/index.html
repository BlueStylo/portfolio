Motion tuning and teleoperation / 2026.07.23 to 07.26

미리 짜둔 타임라인을 재생하는 단계에서, 손으로 직접 끌고 다니는 제어까지 넓혔습니다.

동작이 덜컹거릴 때 감으로 값을 바꾸지 않고, 프로파일과 jerk, 가속, 블렌딩 반경을 한 번에 하나씩만 바꿔 실기에서 비교했습니다. 그다음에는 미리 정해둔 경로를 재생하는 대신 사람이 만든 궤적을 그대로 따라오게 만드는 쪽으로 넘어갔습니다.

01Profile A/B

TOPPRA와 Ruckig, jerk 100 대 20, 가속 50 대 25를 단일 변수로 비교

02Queued MoveJ blend

6개 MoveJ를 미리 queue해 host 간격 제거, 반경 0 대 1mm 비교

03ServoJ live follow

단일 세션, Web Worker 전송, 연속성 시드 IK, 지연 측정으로 반응 약 3.5배

04WebXR teleoperation

Quest 3의 6DoF 포즈를 로봇 좌표계로 변환, bounded target으로 범위 제한

웹 제어 인터페이스는 Source Robotics의 오픈소스 Pilot에서 출발했고, commander 제어 루프, robot_client, kinematics 같은 핵심 경로를 다시 썼습니다. 블렌딩 A/B 러너는 실행 중 command index 소유권을 감시해서, 요청한 jerk, 반경, 속도와 실제 실행값이 다르면 그 자리에서 멈추도록(HALT) 만들었습니다. 이틀 동안 72개 파일에 19,530줄을 더하고 4,798줄을 걷어냈고, IK 런타임과 서보 전송, 좌표 정렬은 브라우저 런타임 검증 스크립트와 계약 테스트로 회귀 확인했습니다.

Unity로 만든 시각용 PAROL6 모델을 Quest 혼합현실 화면에 띄워, 실기기 옆에서 관절 자세가 함께 움직이는 것을 확인했습니다.

VR teach, keyframe and repeat / 2026.07.28

원하는 동작을 VR로 가르치고, 기록한 행동을 다시 반복시키는 단계까지 연결했습니다.

Quest에서 로봇 링크를 잡아 목표 자세를 만들고, Pilot 타임라인의 playhead를 옮기며 현재 joint/TCP 상태를 keyframe으로 순차 저장한 뒤 같은 sequence를 실기기로 반복 실행했습니다. 사람이 자세와 시점을 정해 가르치는 keyframe 기반 teach-and-repeat입니다. 영상 화면의 INPUT ONLY, PILOT OWNS MOTION 원칙처럼 Quest는 목표 입력만 만들고, 실제 실행 소유권은 HOME, limit, stop 상태를 관리하는 Pilot 제어 경로에 남겼습니다.

01Quest target

링크와 관절 grab으로 Desired 자세를 갱신하되, Quest 자체는 motor command를 소유하지 않음

02Keyframe capture

현재 playhead에 joint/TCP 상태를 저장해 사람이 가르친 sequence를 구성

03Authority handoff

실기 Execute 전 Live Control을 해제하고 HOME과 motion enabled gate를 확인

04Queue and repeat

시작 자세 정렬 뒤 검증된 command를 queue하고 지정한 횟수만큼 반복 실행
