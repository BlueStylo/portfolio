P32 / 2026.06.22 / Edge AI Device MVP

MeetKey Recorder

Fusion에서 전용 케이스를 설계하고 출력해 Raspberry Pi 디스플레이와 Anker PowerConf를 하나의 회의실 장비로 조립한 뒤, 사내 서버의 Whisper 전사와 Gemma 요약, 내부 Wi-Fi QR 수령까지 연결한 회의록 녹음기 MVP입니다.

케이스 제작 보기 테스트 개선 보기 개념 도식도 보기
내 역할 회의록 AI 서버 구조 검증, Fusion v3 케이스 설계/출력, Raspberry Pi 장비 UI, Anker PowerConf 녹음, QR 전달, 다운로드 후 삭제 UX, 장시간 회의 요약 프롬프트 개선까지 MVP로 연결
사용 기술 Fusion 360, Bambu Studio, Raspberry Pi, ALSA/arecord, Python server, Whisper large-v3, Ollama Gemma 31B Q8 128k, chunked transcription, QR delivery
결과 2시간 5분 실회의에서 13개 청크 전사/요약과 전체 전사문 최종 병합 구조를 검증하고, 3D 프린팅 케이스 기반 장비형 UX로 확장
공개 제한 내부 Wi-Fi QR 주소는 노출 가능하며, 원본 사진은 메타데이터를 제거한 공개용 이미지로 사용
장비 MVP Fusion v3 case + Pi + mic

화면 공차 테스트 2회 후 v3 전체 케이스를 출력하고 Raspberry Pi와 회의용 마이크까지 조립했습니다

음성 입력 Anker PowerConf

360도 회의용 스피커마이크로 스마트폰 녹음 대비 음성 입력 품질을 검증했습니다

AI 처리 Whisper large-v3 + Gemma

10분 청크 전사/요약과 128k 최종 병합 프롬프트를 실제 2시간 회의로 검증했습니다

보안 UX QR download -> delete

내부 Wi-Fi QR로 받고, 다운로드 이후에는 장비/서버 쪽 기록을 지우는 흐름을 설계했습니다

Case design and fabrication

소프트웨어 MVP를 회의실에 놓을 수 있는 물리 장비로 만들었습니다.

단순히 Raspberry Pi 화면을 세워둔 것이 아니라, 화면 공차를 작은 테스트 출력으로 먼저 확인하고 v3 전체 케이스를 출력했습니다. 디스플레이와 마이크를 조립하는 단계까지 들어가면서 MeetKey는 서버 실험이 아니라 사용 가능한 회의실 장비 MVP가 됐습니다.

Concept architecture

서버 AI 회의록 시스템을 회의실 장비 UX로 끌어낸 구조입니다.

출발점은 같은 녹음 파일을 스마트폰 클로바 앱과 Whisper로 전사했을 때 품질 차이가 크게 보였던 경험이었습니다. 먼저 사내 서버에 Whisper large-v3와 Gemma 요약 흐름을 구현하고, 그 다음에는 사용자가 회의실에서 더 쉽게 쓰도록 Raspberry Pi 장비와 QR 전달 UX로 확장했습니다.

01 / Capture layer 회의실 음성 수집

Anker PowerConf가 회의실 360도 음성을 받음

02 / AI server layer 사내 서버 전사/요약

10분 단위 음성 segment를 서버 작업 큐에 등록

03 / Phone delivery layer 휴대폰 QR 수령

MeetKey AP 연결 QR과 결과 접속 QR을 분리

04 / Retention layer 다운로드 후 정리

사용자가 받은 뒤 save/delete 선택

  • 휴대폰에서 녹음, 전사, 요약 결과 다운로드 또는 복사
  • 마크다운 요약을 읽기 좋은 양식으로 표시

  • 사용자가 받은 뒤 save/delete 선택
  • 보안이 중요한 회의는 다운로드 후 내부 파일 삭제
  • 외부 클라우드에 회의 음성을 남기지 않는 정책

Field test fixes

실제 테스트에서 막힌 지점을 제품 흐름 안에서 해결했습니다.

장비를 직접 써보니 전사 모델보다 먼저 접속 환경, 긴 녹음 처리, 결과 공유, 회의록 읽기 형식 같은 운영 문제가 드러났습니다. 이 문제들을 별도 설명서가 아니라 장비와 휴대폰 UX 안에 넣어 해결했습니다.

Access
다른 사람의 휴대폰은 내부망이 아니었습니다.

제 휴대폰은 내부 Wi-Fi QR로 바로 접속됐지만, 다른 사람은 LTE이거나 다른 Wi-Fi에 붙어 있어 링크가 열리지 않았습니다.

Raspberry Pi에서 AP 테더링 접속 지점을 만들고, QR을 Wi-Fi 연결용과 결과 접속용으로 나눴습니다. 먼저 MeetKey Wi-Fi에 붙고 다음 화면에서 회의록 링크를 여는 2단계 UX로 해결했습니다.

Processing
긴 녹음을 한 번에 보내면 타임아웃과 지연 위험이 있었습니다.

실제 2시간 5분 회의에서는 전체 파일을 한 번에 처리하는 방식보다 청크별 처리 상태와 최종 병합 품질을 분리해 봐야 했습니다.

녹음 중 10분 단위로 음성을 잘라 서버에서 먼저 처리하게 했습니다. 2시간 5분 녹음에서는 13개 청크를 만들고, 종료 후에는 남은 구간과 최종 병합만 처리하는 방향으로 체감 대기 시간을 줄였습니다.

Summary quality
구간 요약만 이어붙이면 회의 결론이 과하게 확정될 수 있었습니다.

긴 회의에서는 앞 구간의 결정 후보가 뒤 구간에서 바뀌거나 보류될 수 있어, 청크 요약을 그대로 최종 회의록으로 쓰면 위험했습니다.

청크 요약은 중간 데이터로 만들고, 최종 병합 단계에서 전체 전사문과 청크 요약을 함께 보며 확정/잠정 합의/검토 필요/제안/단순 언급을 다시 구분하도록 프롬프트를 개선했습니다.

Handoff
다운로드만으로는 회의록을 바로 쓰기 불편했습니다.

휴대폰에서 요약을 받은 뒤 다른 앱이나 메신저에 옮기는 상황에서는 파일 다운로드보다 바로 복사하는 흐름이 더 자연스러웠습니다.

요약 다운로드와 함께 복사 기능을 추가해, 결과 확인 후 바로 문서나 메신저에 붙여넣을 수 있게 했습니다.

Reading
마크다운 요약이 내용은 있어도 형식이 잘 보이지 않았습니다.

요약 결과가 마크다운으로 만들어져도 화면에서 양식이 드러나지 않으면 회의록처럼 읽기 어렵고, 결과 품질도 낮아 보였습니다.

요약 마크다운을 볼 때 제목, 구분, 목록 형식이 보이도록 표시 패치를 적용해 휴대폰 페이지에서도 회의록 양식이 읽히게 했습니다.

Core thinking

이 프로젝트의 핵심은 AI 모델보다 사용 조건을 같이 검증한 점입니다.

회의록 AI를 만들었다는 말만으로는 제품성이 잘 드러나지 않습니다. MeetKey는 음성 입력 장비, 서버 처리 위치, 휴대폰 수령 방식, 기록 삭제 정책까지 하나의 사용 시나리오로 묶어본 실험입니다.

품질 가설

같은 녹음 파일도 스마트폰 앱 전사와 Whisper 전사의 결과 차이가 컸고, 더 좋은 회의용 마이크 입력이 전사 품질을 끌어올릴 수 있는지 확인하고 싶었습니다.

배포 가설

AI 회의록 기능이 서버에만 있으면 쓰기 어렵기 때문에, 회의실에 놓는 작은 장비로 녹음 시작부터 결과 수령까지 낮은 마찰로 묶었습니다.

보안 가설

회의 음성은 민감도가 높아 외부 클라우드보다 사내 서버 처리, 내부 Wi-Fi QR, 다운로드 후 삭제 정책이 더 설득력 있는 UX라고 봤습니다.

운영 가설

전사 서버, QR 페이지, 장비 UI를 분리해두면 이후에는 화자 분리, 요약 템플릿, 관리자 화면을 독립적으로 확장할 수 있습니다.

컨텍스트 가설

2시간 5분 회의의 청크 요약과 전체 전사문은 약 10.6만 자 규모였고, 128k 컨텍스트 안에서 최종 병합이 가능한 범위라고 판단했습니다.

MVP device test

실제 Raspberry Pi 화면과 회의용 마이크로 상태 흐름을 테스트했습니다.

사진은 모두 실제 MVP 장비 테스트 화면입니다. 사용자가 회의 중 장비 앞에서 보는 상태를 중심으로, 대기, 녹음, 일시정지, 처리 QR 화면을 나눠 확인했습니다.

Security and handoff

QR은 공유 링크가 아니라, 내부 Wi-Fi에서만 쓰는 짧은 전달 통로입니다.

회의록은 편해야 하지만 회의 음성은 민감합니다. 그래서 QR 주소를 외부 공개 URL로 보지 않고, 같은 내부망에 있을 때만 접근하는 임시 수령 경로로 설계했습니다.

01 회의 종료

장비가 녹음 파일을 저장하고 사내 서버 처리 상태를 기다립니다.

02 QR 수령

같은 내부 Wi-Fi에 있는 휴대폰에서만 전사와 요약 결과를 내려받습니다.

03 삭제 정책

다운로드 이후에는 장비와 서버 내부에 남은 파일을 지우는 흐름으로 보안 불안을 줄입니다.

Portfolio notes

공개본에서는 장비 사진과 구조를 보여주고, 내부 서버 정보는 걷어냅니다.

QR 화면은 내부 Wi-Fi에서만 접근하는 간단한 주소라 공개 가능 범위에 넣었습니다. 다만 원본 사진은 EXIF/GPS 메타데이터를 제거한 공개용 이미지로 교체했고, 실제 배포본에서도 서버 IP, 사내 경로, 원본 음성 파일명, 회의 내용이 드러나지 않도록 계속 관리할 예정입니다.
