01 RHINO / GRASSHOPPER

Rhino와 Grasshopper 설계 자동화

비스툴 기업부설연구소에서 환자 맞춤형 보형물 설계 과정을 Grasshopper 정의와 작업자 UI로 옮겼습니다. 디자인팀 4명이 모든 설계 건을 이 도구로 처리하고 있고, 긴급 건 리드타임은 5영업일에서 2영업일로 줄었습니다.

  • 7단계작업자 UIHuman UI 기반 단계별 화면
  • 138개정의 버전15,337 오브젝트
  • 373분에서 150분평균 설계시간약 60% 단축, 내부 성과보고서 2026.03 기준
  • 288분에서 60분숙련도 격차설계자 간 소요시간 차이
  • 월 약 150건디자인팀 4명 실사용설계 건 100% 경유
  • Grasshopper에 없는 소프트 변형은 raised-cosine falloff로 라인 메쉬를 변형하는 네이티브 노드로 직접 구현했습니다.
  • 설계자 4명 옆에서 작업을 관찰하고 단계별 소요시간을 측정해 요구사항을 기술 스펙으로 옮겼습니다.

02 GRASSHOPPER / ALGORITHM

Grasshopper 노드로 만든 2.5D 레이캐스팅 엔진

개인 작업으로는 Grasshopper 노드와 C# 스크립트 하나로 2.5D 레이캐스팅 엔진을 만들었습니다(2026.01). 시야각 안에 광선 450개를 뿌려 벽과의 거리로 벽 기둥 높이를 정하고, 방사형 광선 때문에 벽이 휘어 보이는 왜곡을 삼각함수로 보정했습니다.

초기 3D를 만들던 사람들이 어떻게 사고했을지 궁금해서 2026년 1월에 혼자 만든 개인 작업입니다. 2D 지도 위의 플레이어에서 광선을 뿌리고, 가장 가까운 벽까지의 거리를 시선 중심과의 각도로 보정해 기둥 높이로 바꾸는 계산이 캔버스의 그룹 14개에 그대로 남아 있습니다.

  • 벽 곡선 12개(곡선 벽 1개 포함), 시야각 45도, 광선 450개, 객체 190개. 벽 색을 지도의 선 색과 화면의 벽 색에 같이 씁니다.
  • C# 스크립트 하나로 캔버스 키 입력을 받아 16ms 타이머와 경과 시간 기준으로 플레이어를 움직입니다.

03 SITE / 3D RECONSTRUCTION

대지와 건물을 3D로 만들고 웹에서 쓰이게

2026년 9월, 드론 영상 3개에서 682장을 추출해 COLMAP으로 하나의 좌표계에 정합하고(682장 전부 등록, 희소점 344,264개, 평균 재투영 오차 0.47픽셀), Brush로 가우시안 1,688,991개를 학습해 집과 주변 주택과 도로와 논밭을 복원했습니다.

04 3D PIPELINE / ON-PREMISE

3D를 뽑아 설계 입력으로 넣는 파이프라인

CT에서 대상 부위를 자동 분할해 STL로 만드는 파이프라인을 구축했습니다. DICOM을 올리면 웹 큐를 거쳐 Python 파이프라인이 STL을 만들고, 그 STL이 설계 자동화의 입력이 되어 도면과 몰드까지 이어집니다. 수작업 40분에서 90분이 걸리던 일을 대체했습니다.

  • 77케이스학습 데이터셋37,826슬라이스 직접 구축
  • nnU-Net v24종 비교 후 선정Dice 79.83
  • 1,228건파이프라인 실행2026.09 기준 성공률 99.1%, 평균 7.4분
  • RTX PRO 6000 96GB GPU 서버를 도입하고 Linux, Docker, Nginx, systemd로 구성해 온프레미스에서 직접 운영하고 있습니다.
  • 처리 건수, 완료율, 단계별 소요시간을 대시보드로 남겨 운영 근거를 숫자로 확인할 수 있게 했습니다.

05 HOW I WORK

일하는 방식

  1. 후보를 만들어 같은 조건에서 비교한 가지 방법을 정해 놓고 파기보다 후보를 여럿 만들어 같은 조건에서 비교해 고릅니다. CT 분할 모델 4종, 로컬 LLM 실행 환경 3종, 로봇 모션 프로파일 A/B가 그렇게 결정됐고, AI 도구로 실험 속도를 올리되 판단과 검증은 직접 합니다.
  2. 비개발 직군과 요구사항 정의설계자 옆에서 작업을 보고 시간을 재서 스펙으로 옮깁니다. 그렇게 만든 도구가 설계 건 100%를 경유하게 됐습니다.
  3. 규칙과 판정의 경계 설계규칙으로 잡히는 것은 규칙 엔진에, 판단이 필요한 것은 모델에 맡기도록 나눕니다. 제조 검증 봇은 규칙 5종과 로컬 VLM 2종으로 구성해 합성 390건 평가에서 규칙 엔진 false acceptance 0/360을 확인한 뒤 사내 운영에 올렸습니다.
  4. 문서화서버 구성부터 파이프라인 운영까지 MkDocs로 기록해 다음 사람이 그대로 이어받을 수 있게 합니다.
